# 4G 模块安装 + 网络音频使用说明

把树莓派的**降噪麦克风**通过网络送给 Windows 电脑，同时把**电脑的声音**收回到树莓派的
耳机口——给树莓派装上 4G 模块后，这条链路就不再受蓝牙距离限制。

```
       树莓派 5                                    Windows 电脑
  ┌─────────────────────┐                    ┌──────────────────────┐
  │ reSpeaker 麦克风     │                    │  btmic_net_gui.py    │
  │   ↓ arecord         │   上行：降噪后的     │   ↓ 播放到扬声器/耳机 │
  │   ↓ DeepFilterNet   │ ──麦克风音频──────▶ │   （可选录成 WAV）    │
  │   ↓ 增益            │                    │                      │
  │   ↓ 网络桥          │ ◀─电脑声音────────── │   ↑ 采集系统声音回环  │
  │   ↑ 网络桥          │   下行：48k/16k     │     或麦克风          │
  │   ↓ aplay → 耳机口   │                    │                      │
  └─────────────────────┘                    └──────────────────────┘
        └── 4G 模块（USB 网卡）或 WiFi / 网线 ──┘
```

两种连接方式，二选一：

| 方式 | 谁连谁 | 需要什么 | 音质 / 延迟 | 适用 |
| --- | --- | --- | --- | --- |
| **TCP 直连**（默认） | 树莓派 → 电脑 | 电脑能被树莓派访问到：同一局域网即可；跨互联网需要电脑有公网 IP 或端口映射 | 48kHz 立体声，延迟 ~150ms，最好 | 树莓派和电脑在同一个 WiFi/热点；或有公网 IP |
| **MQTT 中继** | 两边都连公共 broker | 只要双方都能上网（4G 也行），**不需要公网 IP、不需要端口映射** | 16kHz 单声道(下行)，延迟 ~400ms；公共 broker 不保证投递（实测每帧 85%~100% 波动，偶尔跳音） | 只有 4G、双方都在 NAT 后面，且能接受偶尔跳音 |

> **模块只接串口（40 脚排针 TX/RX）没用 USB 口时**，看文末"附录 A：串口 + PPP 方案"——那是 2026-09-26 在真机上（Air780EG + 联通物联网卡 + 树莓派 5）一条条调通的完整配方，
> 包括手册上没写、实测才踩到的三个坑。
>
> **想让"4G 直连"也达到最好音质？** 见下面"第七节 · 让电脑能被 4G 访问到"的三种做法
> （同一 WiFi / 端口映射 / 内网穿透），内网穿透（ngrok/frp）在比赛现场最省事。

## 一、4G 模块接线

模块是 **Air780EG DTU 开发板**（4G + GPS/北斗，NANO SIM 卡座）。官方资料：
<https://docs.openluat.com/air780eg/>，本目录 `4G File/` 里是随模块给的资料，
实物接口图见 `接线图/1_模块接口位置.png`。

### 1.1 先分清两件事：模块平时接树莓派，不接电脑

```
正式运行：   树莓派 ──USB 线──▶ 4G 模块 ──(移动网络/互联网)── 电脑        ← 电脑那侧一根线都没有
准备阶段：   电脑   ──USB 线──▶ 4G 模块（刷固件、发 AT 命令、验证能不能上网）
```

数据是走"树莓派 → 4G 模块 → 移动网络 → 互联网 → 电脑"的，电脑只是自己连着网
（WiFi/网线）跑图形界面程序，**不需要和模块有任何线缆连接**。只有一次性的准备
工作（刷 AT 固件、发 `AT+RNDISCALL=1`、验证模块能不能上网）才把模块接到电脑上。

### 1.2 模块板上的接口（对照 `接线图/1_模块接口位置.png`）

| 编号 | 接口 | 干什么用 |
| --- | --- | --- |
| ① | **主接口 XH2.54**（白色 8 针座） | **供电 + TTL 串口**：VCC / GND / TXD / RXD（另有 PWR_EN、DTU_EN、DTR 等）。丝印上的 `VCC GND TXD1 RXD1` 就是它 |
| ② | 网络 / 定位指示灯 | D1 D11 = 信号，D2 = GPS |
| ③ | **micro USB 口** | 烧录固件、看日志、**当 4G 网卡**用。板上丝印写得很清楚："USB口无法供电 必须外部供电" |
| ④ | BOOT 按键 | 刷固件时按住它上电 |
| ⑤ | GPS 独立数据串口 | 本项目用不到，可不接 |
| ⑥ | **4G 天线 IPEX 座** | 必须接（不接也能开机，但网速很慢、链路不稳） |
| ⑦ | 供电指示灯 D9 | 亮 = 板子有电 |
| ⑧ | 有源 GPS 天线 IPEX 座 | 可选 |
| ⑨ | **NANO SIM 自弹卡座**（在板子背面） | 断电插卡，缺口朝里按到弹到位 |

### 1.3 正式使用：模块接树莓派（两根线 + 天线 + 卡）

1. **供电（必须外部供电）**：5~12V / 1A 的电源（能给 2A 更稳，5V/2A 手机充电头最省事）
   接到主接口的 `VCC` 和 `GND`（用配套的 XH2.54 端子线）。**千万别指望 USB 口供电**：
   模块发射瞬间电流很大，靠树莓派 USB 口带会反复重启（现象是 `usb0` 一会儿有一会儿没有）。
   `PWR_EN` 不接（悬空）。
2. **数据线**：micro USB 数据线接到**树莓派任意 USB 口**。必须是 **4 芯数据线**，
   不是只有两根线的充电线——用错线只会供电、不会被认成网卡。
3. **天线**：4G 天线接 ⑥（IPEX 座，扣上去）。
4. **SIM 卡**：NANO 小卡，**断电时插入**，缺口朝里。
5. 树莓派上 `ip -brief addr` 能看到 `usb0` 就成功了（下一节）。

### 1.4 准备阶段：模块接电脑（刷固件 / 发 AT 命令）

- **电源照旧**（仍然要外部供电，USB 口不给板子供电）；
- micro USB 数据线接到**电脑**的 USB 口：Win7 以上自动装驱动，设备管理器里会出现
  "USB 串行设备"这类串口（记下它的 COM 号，发 AT 命令要用）；
- 刷固件时按住 ④ BOOT 再上电（见第二节）；
- 发 AT 命令用串口助手（SSCOM），选那个 COM 口、**115200 / 8 位 / 1 停止 / 无校验**，
  勾上"加回车换行"；
- 顺带可以在电脑上验证模块能不能上网：刷好 AT 固件并开了 `AT+RNDISCALL=1` 之后，
  模块在 Windows 上会多出一个 RNDIS 网卡（Windows 自动装驱动），能上网就说明模块和
  SIM 卡都正常——这一步验完再插到树莓派上，省得两头猜。

### 1.5 可选：用 TTL 串口代替 USB 口

如果不想用 USB 口（或 USB 口要留给别的东西），可以走串口，接法见
`接线图/3_接电脑_TTL串口.png`：需要一个 **USB-TTL 转接板**，接线是**交叉**的——

| USB-TTL 转接板 | 模块主接口（DTU） |
| --- | --- |
| RXD | TXD |
| TXD | RXD |
| GND | GND（**必须共地**） |

转接板电平选 **3.3V**；模块仍然要外部供电。注意这条路**只能发 AT 命令/刷固件，
不能当网卡用**——本项目正式跑的时候必须用 USB 口（③）。

### 1.6 踩坑清单

| 现象 | 原因 |
| --- | --- |
| `usb0` 一会儿有一会儿没、模块反复重启 | 供电不足（用了树莓派 USB 口或弱电源） |
| 电脑/树莓派完全不认模块 | 用了只有 2 根线的充电线 |
| 电脑和树莓派同时连着 USB，两边都异常 | 一个 USB 从机设备不能同时接两个主机，换到一边 |
| `lsusb` 认到模块但没有 `usb0` | ① 模块还在 **RNDIS** 模式（树莓派内核没这个驱动）→ 发 `AT+SETUSB=1` 切 ECM；② 没开网卡功能 → 发 `AT+RNDISCALL=1`；③ 驱动没加载 → `modprobe cdc_ether` 后重新插拔。先跑 `--net-4g`，它会直接告诉你卡在哪一步 |
| 有 `usb0` 但上不了网 | SIM 没流量/欠费、天线没接、APN 问题（`--net-4g` 会一步步提示） |

板上的指示灯含义：D9 供电（亮 = 有电）；D1/D11 信号；D2 GPS（定位后 1 秒亮 1 秒灭）；
NET 指示灯（AT 固件下常亮/有规律闪烁表示驻网正常；DTU 固件下 100ms 闪 = 正在注册网络，
500ms 闪 = 已附着数据网络，亮 100ms/灭 1900ms = 已连上服务器）。

## 二、给模块刷 AT 固件并打开"USB 网卡"功能

> 为什么必须刷：**DTU 固件是"串口透传"用的**，它把串口数据转发到服务器，这条链路的
> 瓶颈在串口（最高 921600，约 90KB/s），而且还要额外的服务器。**AT 固件能把模块当
> 4G 网卡用**（USB 从机模式），树莓派直接拿到一个 `usb0` 网卡、走标准 TCP/IP，
> 带宽和便利性都好得多，本工程的网络模式就是按这个方案写的。

**1）刷固件**（资料：`4G File/AT 固件资料/AirM2M_780E_V1179_LTE_AT.zip`、`Luatools_v2.rar`）

- 模块**断电**，按住板上的 **BOOT** 键不放；
- 给模块**通电**，并**继续按住 BOOT**，直到 Luatools 提示可以松开；
- 电脑用 USB 线连模块，打开 `Luatools_v2`，选"下载固件"→ 选固件文件 → 开始下载；
- 如果不按 BOOT 就能正常进入下载也可以，按提示操作即可。

**2）选对"USB 网卡模式"：树莓派上必须用 ECM，不能用默认的 RNDIS**

这一步很多人会踩：模块默认是 RNDIS 模式，而**树莓派内核里没有 RNDIS 主机驱动**，
插上去 `lsusb` 能看到模块、但**永远不会有网卡出现**。我查过树莓派官方内核的
配置文件（`rpi-6.6.y` / `rpi-6.1.y` 的 `bcm2712_defconfig` 与 `bcm2711_defconfig`，
两个版本结论一致）：

| 内核选项 | 树莓派官方内核 | 说明 |
| --- | --- | --- |
| `CONFIG_USB_NET_CDCETHER` | **`=m`（有）** | **ECM 网卡的驱动，树莓派要用这个** ✓ |
| `CONFIG_USB_NET_CDC_NCM` / `CDC_EEM` | `=m`（有） | NCM / EEM 也能用（模块默认不是这两种） |
| `CONFIG_USB_NET_RNDIS_HOST` | **没有这一项** | RNDIS 主机驱动缺失，模块默认模式用不了 ✗ |
| `CONFIG_USB_SERIAL_OPTION` | `=m`（有） | 模块的 AT 串口会枚举成 `/dev/ttyUSB*` ✓（好处见下） |

> 顺带说明：这两个驱动都是 **Linux 主线内核自带**的，属于标准 USB 设备类，
> **不需要装厂商驱动、也不用自己写驱动**；Debian 官方内核同样带 `cdc_ether`，
> 所以普通 Debian arm64 上也一样能用（只是要确认没被 blacklist）。
> defconfig 里出现的 `CONFIG_USB_NET_RNDIS_WLAN` 是给 RNDIS 无线网卡用的、
> `CONFIG_USB_CONFIGFS_RNDIS` 是"树莓派自己当 RNDIS 从机"用的，都不是主机侧网卡驱动。

所以要发两条 AT 命令（`4G File/AT 固件资料/…AT命令手册V1.6.8.pdf` 第 4.28/4.29 节）：

```
AT+RNDISCALL=1        ← 打开网卡功能（必需，重启生效）
AT+SETUSB=1           ← 切成 ECM+AT+PPP+DIAG（树莓派必需，重启生效）
```

`AT+RNDISCALL` 需要固件版本 >= V1140（上面的 V1179 满足）。

**3）在树莓派上直接发这两条命令**（不用再抱一台电脑来）

因为 `CONFIG_USB_SERIAL_OPTION` 在，模块的 AT 口会枚举成 `/dev/ttyUSB*`，所以把模块
插到树莓派上就能发 AT 命令（程序会自动找到 AT 口、自动停掉会抢串口的 ModemManager）：

```bash
sudo python3 final_btmic.py --net-4g-at 'AT+RNDISCALL=1'
sudo python3 final_btmic.py --net-4g-at 'AT+SETUSB=1'
sudo python3 final_btmic.py --net-4g-at 'AT+CGATT?'      # 1 = 已附着数据网络
```

发完**给模块断电重启**（AT 命令注明"重启生效"），然后：

```bash
sudo python3 final_btmic.py --net-4g-setup    # 加载 cdc_ether + 要 IP + 验证联网
```

想用电脑发也行（SSCOM，115200-8-N-1，勾"加回车换行"），命令一样。
万一模块已经插在树莓派上、而你想在电脑上发命令，注意**不能两边同时插 USB**。

## 三、树莓派侧：让 4G 模块变成网卡

插好模块（外部供电 + USB 数据线）后，在树莓派上执行：

最省事的做法是让程序替你做完：

```bash
sudo python3 final_btmic.py --net-4g-setup
```

它会：扫 sysfs 看模块是 RNDIS 还是 ECM → 需要时加载 `cdc_ether` → 给网卡要 IP
（依次试 `dhclient` / `udhcpc` / `nmcli`）→ ping 一下验证，并把"还差哪一步"打出来。

想手工一步步来：

```bash
# 1) 看 USB 有没有认到模块（合宙 EC618 的 VID:PID 是 19d1:0001）
lsusb

# 2) 看模块现在是 RNDIS 还是 ECM、各接口有没有绑定驱动（不用 root）
#    0206 = ECM ✓   e003 = RNDIS ✗   ffff = 厂商口（AT/日志）
for d in /sys/bus/usb/devices/*/; do
  [ "$(cat $d/idVendor 2>/dev/null)" = "19d1" ] &&     echo "$d $(cat $d/idProduct) $(cat $d/*/bInterfaceClass 2>/dev/null)"
done

# 3) 看有没有网卡，以及它绑的是哪个驱动
ip -brief addr
for n in /sys/class/net/*; do
  [ -e "$n/device/driver" ] && echo "$n -> $(readlink -f $n/device/driver | xargs basename)"
done

# 4) 网卡没出现：加载 ECM 驱动，然后重新插拔 USB 线（驱动加载后要重新枚举）
sudo modprobe cdc_ether

# 5) 有网卡但没 IP：要一次地址（Raspberry Pi OS 一般会自动拿）
sudo dhclient -1 usb0        # 网卡名以 ip -brief addr 显示的为准

# 6) 验证真的能上网
ip route                     # 默认路由应该走 usb0（或 enx…）
ping -c 3 223.5.5.5
```

本程序自带一条只读诊断命令，会把上面这些一次性检查完，并直接告诉你"下一步该做什么"
（模块没识别 / 模式不对 / 没绑驱动 / 没 IP / 不能上网，五种情况给不同命令）：

```bash
sudo python3 final_btmic.py --net-4g
```

> **注意**：模块的 USB 口会同时枚举出几个串口（AT 口 / 日志口），**ModemManager 会去抢
> 这些串口**，抢到之后网卡可能反复断线。本程序进入网络模式时会自动停掉 ModemManager
> 和 PulseAudio/PipeWire（后者是为了独占声卡，和蓝牙模式同一套做法），所以直接跑
> `--net` 就行。要恢复桌面音频（不想让它一直停着）：
>
> ```bash
> systemctl --global unmask pipewire.socket pipewire-pulse.socket pulseaudio.socket
> sudo systemctl start pipewire pipewire-pulse
> ```

## 四、Windows 电脑端：图形界面程序

```
windows/
├── btmic_net_gui.py     ← 图形界面主程序
├── 启动.bat             ← 双击它（会自动装依赖再启动）
└── requirements.txt
```

**首次使用**：把 `windows` 整个文件夹拷到电脑上，双击 **`启动.bat`**（会自动执行
`pip install soundcard numpy` 再启动界面）。也可以手动：

```bat
pip install -r requirements.txt
python btmic_net_gui.py
```

界面从上到下五块：

1. **连接设置**：选 `TCP 直连` 或 `MQTT 中继`，填端口 / broker / **令牌**。
   令牌是两边必须一致的"暗号"（点"换一个"生成）。填完点 **启动服务**。
2. **上行：树莓派麦克风 → 电脑**：选播放设备（耳机或扬声器）、音量、静音；
   勾"同时录音到 WAV"可以把收到的降噪音频存成文件（演示/取证都方便）。
3. **下行：电脑声音 → 树莓派耳机口**：选采集来源——
   `系统声音 · xxx（回环）` = 电脑正在播放的所有声音；`麦克风 · xxx` = 你说的话。
   还有 **远端麦克风增益** 滑块（相当于电脑上给树莓派麦克风调音量，0~15）。
4. **状态**：连接状态、收到/发出的帧数、抖动缓冲、往返延迟。
5. **日志**：每一步都写在这里；出问题先看它。

底部按钮：**音频自检**（列出设备、放一段 1kHz 测试音、抓 1 秒电平，几秒钟就能判断
"电脑这边到底有没有声音"）、**刷新设备**、**把连接参数复制给树莓派**（生成一条可以直接
粘到树莓派 SSH 里执行的命令，含地址/端口/令牌——省得手抄出错）。

## 五、树莓派端：跑起来

```bash
# 先把**新的** final_btmic.py 覆盖到树莓派上（网络模式全在这一个文件里，不用别的依赖）
# TCP 直连（电脑和树莓派在同一局域网时）
sudo python3 final_btmic.py --net --host 192.168.1.100 --port 5010 --token ab12cd

# MQTT 中继（只有 4G、双方都在 NAT 后面时）
sudo python3 final_btmic.py --net --transport mqtt \
     --host broker.emqx.io --port 1883 \
     --host-down broker.emqx.io --port-down 1883 \
     --prefix btmic --token ab12cd
```

> 最省事的做法：在 Windows 界面上点 **"把连接参数复制给树莓派"**，它会按当前界面里的
> 设置生成上面这条命令，直接粘到树莓派 SSH 里执行即可（两边令牌自然一致）。

其它命令：

| 命令 | 作用 |
| --- | --- |
| `--net-4g` | 只读检查模块/驱动/模式/上网状态，并按"卡在哪一步"给出具体命令 |
| `--net-4g-setup` | 自动加载驱动 + 要 IP + 验证联网（尽量把模块弄上网） |
| `--net-4g-at 'AT+...'` | **从树莓派给模块发 AT 命令**（自动找 `/dev/ttyUSB*` 里的 AT 口），切 RNDIS/ECM 模式、查驻网状态都用它 |
| `--net-4g-ppp-up` | **串口 PPP 拨号**（一条命令搞定：跳出数据模式 → 写 chat/peer → 拨号 → 等 ppp0 → 验证上网）；APN 用 `--apn WONET` 指定 |
| `--net-4g-ppp-down` | 挂断 PPP 并把模块拉回命令模式 |
| `--net-probe` | 只测"能不能连上电脑"，不碰声卡（退出码 0 = 通） |
| `--net-status` | 看当前会话状态（上行/下行帧数、丢帧、抖动缓冲、电平） |
| `--net-install` | 装 `bt-mic-net.service`，开机自动进网络模式 |
| `--net-uninstall` | 卸载上面这个服务 |
| `--status` / `--df-info` | 降噪模式 / DeepFaceFilter 安装情况（和蓝牙模式共用） |

**开机自启**：

```bash
# 1) 把对端地址写进配置（服务启动时读它）
echo 'NET_HOST=192.168.1.100' | sudo tee -a /etc/default/bt-mic
echo 'NET_PORT=5010'          | sudo tee -a /etc/default/bt-mic
echo 'NET_TOKEN=ab12cd'       | sudo tee -a /etc/default/bt-mic

# 2) 装服务
sudo python3 final_btmic.py --net-install
journalctl -u bt-mic-net -f     # 看日志
```

> 蓝牙模式的 `bt-mic.service` 和网络模式的 `bt-mic-net.service` **不要同时"启用"**
> （同一块声卡只能被一个进程独占）。但不用手动切换：网络模式自己会看情况开关蓝牙
> （见下面「六bis」——没网络连接时自动拉起蓝牙、连上电脑自动停蓝牙）。想手动切就用
> `--switch bt|net`。

## 六、配置项（写进 `/etc/default/bt-mic`，KEY=VALUE）

和蓝牙模式共用同一个配置文件，网络相关的键：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `NET_TRANSPORT` | `tcp` | `tcp`=直连 / `mqtt`=中继 |
| `NET_HOST` / `NET_PORT` | 空 / 5010(tcp)、1883(mqtt) | TCP：电脑 IP；MQTT：broker 地址 |
| `NET_HOST_DOWN` / `NET_PORT_DOWN` | 同上行 | 下行专用 broker（分开走能多一倍带宽） |
| `NET_PREFIX` | `btmic` | MQTT 主题前缀 |
| `NET_TOKEN` | 空 | 连接令牌，两端必须一致（MQTT 下同时是主题名） |
| `NET_FRAME_MS` | 40(tcp) / 120(mqtt) | 一帧多少毫秒。公共 broker 实测只扛得住 ~8 条/秒，中继必须用大帧。**4G 实测推荐 200ms（每方向 5 条/秒）** |
| `NET_UPLINK_RATE` / `NET_UPLINK_CHANNELS` | 16000 / 1 | 上行（降噪输出）格式。想省带宽可写 8000/1（声音会闷一点）。**4G 实测：这条链路一个方向稳定只跑得动 ~45KB/s**。当前这台设的是上下都 16000(各 32KB/s)；想让链路更空、延迟更低，可降到上行 12000(24KB/s)+下行 8000(16KB/s)（电话音质）——**必须在换过新 exe 之后改**，旧版程序不跟随宣布格式 |
| `NET_DOWNLINK_RATE` / `NET_DOWNLINK_CHANNELS` | 48000/2(tcp)、16000/1(mqtt) | 下行格式。4G 慢就降到 `8000`/`1`（16KB/s）。**这个值会通过 hello 告诉电脑端，电脑端按它发**——两边不一致的后果见排查手册"声音失真/非常低沉" |
| `NET_JITTER_MS` | 120(tcp) / 300(mqtt) | 接收侧抖动缓冲目标深度 |
| `NET_MAX_LATENCY_MS` | 500(tcp) / 600(mqtt) | 积压上限，超过就丢最旧（宁可跳一下也不让延迟越堆越高） |
| `NET_SEND_QUEUE_MS` | 400(tcp) / 1500(mqtt) | 发送侧最大排队时长，超出丢最旧（中继给大一些，扛公共 broker 的卡顿） |
| `NET_PEER_TIMEOUT` | 20 | 多少秒收不到对端数据判为掉线 |
| `NET_PROBE_INTERVAL` | 5 | 等电脑上线时每隔几秒探一次 |
| `NET_RETRY_SECS` | 4 | 连不上电脑时每隔几秒重试一次（无限重试，谁先开机都行） |
| `NET_AUTO_BT` | 1 | 智能切换蓝牙：没有网络连接时自动拉起蓝牙服务，连上电脑就自动停蓝牙 |
| `NET_OFFLINE_SECS` | 15 | 上下行都在重连超过这么久，就判定"电脑不在了"，结束会话（把蓝牙还回来） |
| `NET_DOWNLINK_ENABLE` | 1 | `0` = 只上行（不往耳机口放电脑的声音） |
| `NET_ENABLE` | 0 | `1` = 不带 `--net` 参数也直接进网络模式（服务用） |
| `PLAYBACK_DEVICE` | 自动挑 | 耳机输出设备。**推荐留空让程序自己挑**（挑"与麦克风不同卡"的那张）。要写就写设备名，可以写多个（逗号分隔）：第一个是主设备，其余同时送（镜像），插哪个孔都响。⚠️ 别用 `CARD=名字` 钉死：两个同型号 dongle 的 id 重启后会互换——详见「八、排查手册」"电脑→树莓派没声音"第 2b 条 |
| `MIC_DEVICE` | 自动挑 | 麦克风设备，**推荐留空**（程序会验一遍能不能真采到音）。写错会打不开，程序会自己重新挑一个并打印说明 |

带 `--xxx` 的命令行参数优先级最高（`--host` / `--port` / `--token` / `--down-rate` …）。

## 六bis、谁先开机都行：自动重连 + 智能切换蓝牙

**问题**：以前树莓派先开机、电脑端后启动服务，树莓派就连不上了（启动时只试一次）。
现在两边都补上了：

### 1) 无限重试

连不上电脑就每 `NET_RETRY_SECS`（默认 4）秒重试一次，不退出、也不报错退出，日志里能看到：

```
=== 会话 1：等待 Windows 电脑上线（broker.emqx.io:1883） ===
  -> 连不上（[Errno 111] Connection refused）：4 秒后重试（第 1 次）…
  -> 连不上（timed out）：4 秒后重试（第 5 次）…
  -> 已连上 Windows 电脑
```

会话中途掉线也一样：上行/下行两个子进程各自回到"重试"状态（状态文件里
`state=reconnecting`，`--net-status` 看得到），电脑端一回来就自动接上，**不用重启任何一边**。

### 2) 智能切换蓝牙（`NET_AUTO_BT=1`，默认开）

| 状态 | 蓝牙服务 | 说明 |
| --- | --- | --- |
| 开机后电脑还没上线 | **自动拉起** | 手机/电脑可以照常用蓝牙，网络模式在后面等着 |
| 探到 Windows 电脑上线 | **自动停掉** | 腾出麦克风/声卡走网络（两者都要独占同一块声卡） |
| 电脑下线超过 `NET_OFFLINE_SECS` | **自动拉回** | 会话结束 → 麦克风释放 → 蓝牙重新可用 |

时序（实测，树莓派先开机、电脑后启动服务）：

```
14:31:04 === 没有网络连接：启动蓝牙服务（手机/电脑可继续用蓝牙） ===
14:31:25   -> 蓝牙已就绪（bt-mic.service active）
（……这段时间用蓝牙通话……）
15:02:11   -> 已连上 Windows 电脑
15:02:12 === 检测到网络连接：关闭蓝牙服务，腾出麦克风给网络模式 ===
```

关掉这个行为：`echo 'NET_AUTO_BT=0' | sudo tee -a /etc/default/bt-mic`。

> **注意**：两个服务的 unit 里**故意不写** `Conflicts=`。systemd 的 `Conflicts` 是双向的，
> 网络模式去 `systemctl start bt-mic` 拉起蓝牙时，systemd 会顺手把网络服务自己停掉
> （症状：日志里"启动蓝牙服务"紧跟着 "Stopping bt-mic-net.service"，服务莫名其妙退出）。
> 互斥改由程序保证：开会话前停蓝牙、切换用下面这条命令。

### 3) 手动切换

```bash
sudo python3 /home/wanjin1234/denoise_mic/final_btmic.py --switch bt    # 改用蓝牙模式（停掉网络服务）
sudo python3 /home/wanjin1234/denoise_mic/final_btmic.py --switch net   # 改用网络模式（停掉蓝牙服务）
```

## 七、让电脑能被 4G 访问到（想让音质最好就看这节）

树莓派的 4G 是运营商大内网，**外面连不进来**；能不能走 TCP 直连（48kHz 立体声、
延迟 ~150ms），取决于"电脑能不能被树莓派连上"。三种做法，从省事到麻烦：

**做法 1：同一个局域网（最简单）**
电脑连 WiFi，树莓派也连同一个 WiFi（树莓派 5 自带 WiFi，4G 模块可以同时插着）。
这就不需要 4G 参与传输，音质延迟都最好。跑 `--net --host <电脑IP>` 即可。

**做法 2：内网穿透（4G 场景推荐，比赛现场最省事）**
电脑上装个穿透工具，把界面的监听端口暴露到公网，树莓派连那个公网地址：

```bat
:: 电脑上（任选一种）
:: ① ngrok（注册免费账号，免费版给 1 条 TCP 隧道）
ngrok tcp 5010
::   输出形如 tcp://6.tcp.ngrok.io:12345 —— 树莓派就填这个地址和端口

:: ② frp（有公网服务器时）
frpc.exe -c frpc.ini      :: [tcp] local_port=5010 remote_port=6010
```

```bash
# 树莓派侧（注意端口是穿透工具给的那个，不是 5010）
sudo python3 final_btmic.py --net --host 6.tcp.ngrok.io --port 12345 --token ab12cd
```

**做法 3：端口映射 + 公网 IP**
家里宽带如果是公网 IP（电信/联通多数是），在路由器上把 5010 端口映射到电脑的
局域网 IP，树莓派填家里的公网 IP。运营商给了 CGNAT（10.x/100.64.x 开头的地址）
就不行，只能走做法 2 或中继。

**做法 4：自建 broker（中继模式的"稳定版"）**
公共 broker 是免费共享的，不保证投递。如果有一台带公网 IP 的机器（云服务器），
自己跑一个 mosquitto 就彻底稳了：

```bash
# 云服务器上（Ubuntu/Debian）
sudo apt install -y mosquitto
sudo sed -i 's/^# *listener 1883/listener 1883\nallow_anonymous true/' /etc/mosquitto/mosquitto.conf
sudo systemctl restart mosquitto
# 云服务器的安全组/防火墙放开 1883
```

```bash
# 两边都指向它（电脑界面里 Broker 填云服务器 IP，树莓派命令行同样）
sudo python3 final_btmic.py --net --transport mqtt --host <云服务器IP> --port 1883 \
     --prefix btmic --token ab12cd
```

## 八、排查手册

**连不上（日志里一直"连不上，5 秒后重试"）**

电脑端**后启动也没关系**：树莓派会每 4 秒重试一次（`NET_RETRY_SECS`），电脑端一点
"启动服务"就自动接上。真连不上时按下面对：

1. Windows 上有没有点 **启动服务**？状态栏是不是"等待树莓派连接…"？
2. 地址对不对：TCP 直连时树莓派填的必须是**电脑的 IP**（界面"监听端口"旁边就显示
   本机可用地址）。跨互联网时电脑要有公网 IP，或用路由器把 5010 端口映射到电脑。
3. **Windows 防火墙**会挡入站连接：第一次点"启动服务"时如果弹出防火墙提示，选
   **允许访问**（专用网络和公用网络都勾）。已经挡掉的：控制面板 → Windows Defender
   防火墙 → 允许应用通过防火墙 → 找 Python → 勾上。
4. 令牌/主题两边是不是一模一样（大小写敏感）。
5. 用 `sudo python3 final_btmic.py --net-probe` 单独测连通性，它会把失败原因打出来。
6. 4G 侧先确认自己能上网：`--net-4g`，或 `ping -c 3 223.5.5.5`。

**只有一边有声**

- 树莓派→电脑没声音：界面第 ② 块的电平表有没有跳？没有跳说明电脑没收到东西，看
  "上行"状态行的帧数；有跳但听不到，检查电脑的播放设备和系统音量。
- 电脑→树莓派没声音：按"数据到没到声卡"分两层查。
  1. **先看数据到没到**：界面第 ③ 块的电平表有跳吗？没跳说明采集来源选错了（选成
     某个没在出声的设备）；树莓派上 `cat /tmp/btmic_net_down.txt` 看 `recv_frames`/
     `played_frames` 涨不涨、`level_db` 有没有量——涨着而且 level_db 正常（比如 -20
     dBFS），说明音频已经写进声卡了，问题在"写进了哪张卡/哪个孔"。
  2. **再看写进了哪张卡**：**优先什么都别写**——`MIC_DEVICE` / `PLAYBACK_DEVICE`
     留空，程序自己挑：麦克风挑"唯一真能采到音的那张"，耳机挑"与麦克风**不同卡**的
     那张"（跨卡就没有抢时钟的问题）。只有自动挑错时才手工指定，见下面第 2b 条。
  2b. **别用 `CARD=名字` 去"钉死"设备**（2026-09-27 实测踩坑）：两个**同型号** USB
     dongle 的声卡 id（`Audio` / `Audio_1`）是按枚举顺序给的，**重启后会互换**——
     钉死名字的结果就是"放音送到麦克风那张卡、耳机一声没有"，而且每次重启可能换一种
     错法。真要写死就认 USB 物理口（`ls /dev/snd/by-path/`）或者干脆用"不同卡"这条
     规则让程序自己挑。拿不准耳机插在哪张卡上：`sudo python3 final_btmic.py
     --find-output` 会逐张卡放测试音，听到哪张就是哪张。
  3. **想两个孔都响**：`PLAYBACK_DEVICE` 可以写**多个**（逗号分隔），第一个是主设备，
     其余的都同时送（镜像），插哪个孔都响：
     ```
     PLAYBACK_DEVICE=plughw:CARD=Audio_1,DEV=0,plughw:CARD=Audio,DEV=0
     ```
     注意别把"麦克风自己那张卡"当镜像：同一路 USB 时钟既采又放会互相挤（放音
     underrun、麦克风 overrun），那一路容易断续。
  4. **耳机音量被写成 0%**（"有数据、但耳机里几乎没声/断断续续"）：先看
     `amixer -c <卡号> sget Headphone` 是不是 `0 [0%] [-50.00dB]`。实测有两个来源：
     ① 蓝牙脚本里 `amixer cset name='Headphone' unmute` 会把 0 写进去（cset 按原始值
     解释，`unmute` 就写 0），2026-09-27 已修（两个脚本都改成"cset 只用于数值"）；
     ② 网络模式的混音看门狗会在会话中每几秒复查并重设，日志里能看到
     `!! 耳机口混音被改回默认…重新设置`。修完之后实测 45 秒内音量稳定在 100%。
  5. **这台机器实测的声卡地图**（换过线/换过 dongle 后照这个重新确认一次）：
     ```
     card2  id=Audio        KT USB Audio  [只有播放]      ← 耳机插在这张卡的 3.5mm 孔
     card3  id=Audio_1      KT USB Audio  [麦克风 + 播放] ← 面罩麦克风插在这个 dongle
     card4  id=seeed2micvoicec  reSpeaker HAT 的 3.5mm 孔（本机放音不通：aplay 报 I/O error）
     ```
     （注意：这两张 dongle 的卡号/id **每次开机可能互换**，所以配置里两类设备名都别写，
     让程序自动挑——挑出来的正是"麦克风=card3、耳机=card2"，而且两者不同卡。）
     怎么自己确认耳机在哪张卡：往那张卡放一段测试音，同时看"麦克风听见没"——
     `aplay -D plughw:CARD=xxx,DEV=0 某.wav` 期间 `cat /tmp/btmic_net_up.txt` 的
     `level_db` 会明显抬起来（耳机就在那张卡上）。实测数据：往耳机那张卡放 900Hz，
     面罩麦克风电平抬 **+15.7 dB**；往麦克风那张卡放，几乎没变化（-0.6 dB）。

**咔咔响 / 断续**
- 4G 信号弱、带宽不够：把下行降下来 `NET_DOWNLINK_RATE=16000`、`NET_DOWNLINK_CHANNELS=1`，
  帧长加到 `NET_FRAME_MS=160`。日志里"下行 dropped/starved"会明显增长。
- MQTT 中继带宽不足：把 `NET_HOST_DOWN` 换成另一个 broker（例如
  `test.mosquitto.org`），上下行各占一路；或自建 broker（同一台机器跑 mosquitto 即可）。
- 树莓派 CPU 跟不上降噪：看 `--status` 里的 RTF，>0.9 就是吃紧，会自动降到轻量谱减法。

**声音失真 / 非常低沉 / 像慢放（变调）——2026-09-27 定位并修复，最重要的一条**

症状：耳机里有声音，但**低沉、发闷、像慢放**，同时电脑端看到"延迟"一直涨。
根因：**电脑端没按树莓派宣布的格式发下行**。它用了界面上那套设置（16kHz），而树莓派
按自己宣布的 8kHz 播 → **半速 + 低八度**；数据量还翻倍（32KB/s vs 16KB/s），树莓派
的抖动缓冲丢掉一半的帧，听感就是"又低又破"，同时队列越堆越长（延迟一直在涨）。

为什么电脑端没跟上：树莓派的"下行 hello"本来带着格式（`audio: {rate, channels,
frame_ms}`），但电脑端的采集线程是**在收到 hello 之前**就被"对端在线"触发起来的
（那个"在线"是被树莓派的 pong 提前点亮的）→ `fmt` 还是空的 → 退回用界面设置值。
2026-09-27 已在电脑端修好（`_on_hello` 收到 down 通道 hello 才起采集、格式变了自动重起、
`_supervise_loop` 也要求"格式已知"才起）。

> **用了界面程序的，必须换成本次重新打包的 `树莓派网络麦克风.exe`**（旧版有这个 bug；
> 旧 exe 已改名为桌面上的 `旧版exe备份-可删.exe`，把正在跑的界面关掉、重新双击新的
> `树莓派网络麦克风.exe` 即可）。修好后电脑端日志里会写 **"按树莓派宣布的格式"**，
> 看到这行就对了；如果写的是"用界面上的设置值"，说明还在用旧版。

怎么自查这一条（不用听声音）：

```bash
# 树莓派宣布的下行格式
grep '^audio=' /tmp/btmic_net_down.txt
# 收到的帧速率：应等于 "实时帧率"（rate/1000/frame_ms），比如 8kHz+200ms → 5 帧/秒。
# 明显偏高（收到 2 倍）就是电脑端格式不对，正在变调播放
grep -E '^(recv_frames|played_frames|dropped_frames)=' /tmp/btmic_net_down.txt
```

另外，电脑端采集设备的**降采样**（48kHz→8kHz）也补上了抗混叠低通（窗函数 sinc，
实测 5kHz 以上压到 −58~−66dB）：以前用线性插值直接抽点，会把高频折回可听频段，
听起来是沙哑的杂音——这也是一类"失真"。

**延迟「从连上之后一直往上涨」（2026-09-27 实测定位到两个发送侧 bug，均已修）**

症状：刚连上时还好，传输一段时间后电脑端显示的延迟一路上涨。原因是树莓派把音频
**发多了**——4G 一条方向只稳定跑 ~45KB/s，发超了就只能堆在模块/链路缓冲里，越堆越久：

1. **上行发送节拍错**：原来每帧按 `frame_ms/1.5` 推进（等于长期 1.5 倍速发），
   电脑端收到 1.5 倍数据 → 播放队列顶到上限、丢三分之一。实测电脑端收到
   7.5 帧/秒（应 5.0）、音频内容 1.5 倍速。修好后实测 **5.03 帧/秒、1.007 倍**。
2. **μ-law 之后帧长算错**：播放节拍用"编码后的 bytes_per_ms"（μ-law 减半）而帧字节数
   是解码后的 → 每帧被当成两倍时长播 → 又慢又丢一半帧。现在统一按 s16le 的帧长算。

配合下面的 μ-law，链路占用从 ~74% 降到 **32~39%**，4G 链路自己 ping 的 RTT 从
avg 102ms 回到 **avg 45ms**（min 25ms）——余量有了，延迟就不会再往上堆。

**音频编码：μ-law（默认 auto，自动协商）**

树莓派和电脑端握手时会互相报"支持哪些编码"，两边都支持 μ-law 就自动切过去：

| 项 | PCM（原） | μ-law（现在） |
| --- | --- | --- |
| 每方向数据量 | 16kHz 单声道 32KB/s | **16KB/s**（每样本 8bit） |
| 语音带宽 | 8kHz | **8kHz（不变）** |
| 音质 | — | 往返 SNR 35~39dB（电话级，语音透明） |
| 4G 占用（上下各 45KB/s 上限） | 各 ~74% ✗ | **各 ~32%** ✓ |

`NET_CODEC=auto`（默认）/ `pcm`（老式，不压缩）/ `ulaw`（强制）。**只有电脑端也支持
才会切**——所以旧版电脑端程序照旧用 PCM，不会被打乱（但也享受不到降带宽的好处）。
μ-law 只在 MQTT（4G/公网中继）上启用；TCP 直连是局域网，带宽够，仍用 PCM。

**延迟大（"说话要过好几秒才听到"）——先量清楚是哪一段**

链路里一共有五段缓冲，加起来才是听到的延迟。逐段量，别整段猜：

| 段 | 看哪里 | 正常值 | 调法 |
| --- | --- | --- | --- |
| 电脑端采集送发 | 界面第 ③ 块状态行的"上行/下行帧数" | 一块 120ms | `NET_FRAME_MS` |
| broker 中转（互联网） | 界面"往返延迟"（RTT，就是它发的 ping/pong） | 50~500ms（4G 差时 1s+） | 换 broker / 自建 / 走 TCP |
| 树莓派抖动缓冲 | `cat /tmp/btmic_net_down.txt` 的 `jbuf_ms` | 240~400ms | `NET_JITTER_MS`（调小=延迟低但更容易断音） |
| 树莓派播放缓冲 | — | 200ms（`--buffer-time`） | `HP_BUFFER_TIME_US` |
| 电脑端播放缓冲 | 界面第 ② 块 | ≈300ms（超过就自动裁剪） | — |

**判断标准**：`jbuf_ms` 长期贴在 `NET_JITTER_MS` 上、`dropped_frames` 一直涨，说明
不是"延迟"而是**上游发得比播得快**（或播放设备被别的进程占着）；`jbuf_ms` 忽高忽低、
`starved_frames` 涨，是**链路卡顿**（4G 信号/公共 broker 抖动）。

2026-09-27 实测的一次干净会话（4G + 公共 broker）作为对照：

```
下行: 收到 8.3 帧/秒（≈实时）播放 8.3 帧/秒  丢 0.00 帧/秒  抖动缓冲 240ms
上行: 发出 8.3 帧/秒（≈实时）             丢 0.00 帧/秒  积压 0ms
```

**当时"延迟很大 + 声音失真"的真实原因**（三个 bug，均已修）：
① 蓝牙脚本把耳机音量写成 0%（见上"耳机音量被写成 0%"），音量在 0 和 100% 之间跳，
听感就是"忽大忽小、断断续续、还以为是延迟"；
② 配置里把两张同型号 dongle 写成 `CARD=Audio` / `CARD=Audio_1`，重启后 id 互换 →
放音送到麦克风那张卡（同卡抢 USB 时钟 → 一会 underrun 一会丢帧）；
③ 放音/采集撞在同一张卡时，下行会被时钟差拖慢（数据到得比播得快 → 堆缓冲 → 跳音）。
现在设备全自动挑、两个方向强制分开走不同卡，实测 60 秒 0 丢帧、缓冲稳定 240ms。

**树莓派上插了模块但一直没有网卡（`ip -brief addr` 里没有 usb0/enx*）**

先跑 `sudo python3 final_btmic.py --net-4g`，它会区分五种情况并给出对应命令：
模块没识别 / 还在 RNDIS 模式 / 已是 ECM 但没绑驱动 / 有网卡没 IP / 有 IP 不能上网。
最常见的就是"还在 RNDIS 模式"——树莓派内核没有 RNDIS 主机驱动，必须
`--net-4g-at 'AT+SETUSB=1'` 切成 ECM 并断电重启模块。

**树莓派端听电脑声音「断续、发闷」（2026-09-27 实测定位并修复）**

先看 `/tmp/btmic_net_down.txt`：如果 `dropped_frames` 很大、`jbuf_ms` 顶在上限，就是
"播放侧供不上"。实测根因是**低速下行会被某些 USB 声卡播慢**：本机那块 KT USB 声卡
（`plughw:2,0`）播 8000Hz 时 **10 秒的数据要 12.5 秒才播完**（16000Hz 要 11.3 秒，
48000Hz 才 10.26 秒）→ 下游反压 → 抖动缓冲堆满 → 丢 70%+ 的帧（实测 456/614），
听感就是断续 + 发闷。

程序现在自动处理：**下行速率低于 `NET_HP_RATE`（默认 48000）时，先在树莓派这边用
FIR 重采样到设备原生速率，再让 aplay 按原生速率播**。同场景复测：丢帧 456 → **0**，
抖动缓冲 480ms → **80ms**；日志里会打印
`下行 8000 Hz 1 ch → 重采样到设备原生 48000 Hz`。

同时修了两个相关缺陷：① 复用的重采样脚本只支持多声道，**单声道输入直接抛
`ValueError`**（每级管道启动即退出、会话反复 failed）→ 已修（单声道先 `ravel` 压成一维）；
② 下行消费端在队列满时**空转占满一个 CPU 核**，拖累上行降噪 → 已改为睡到该写的时刻。

**音质本身**（与断续无关）：8000Hz 单声道就是电话音质，音乐听着必然闷。
- **同一 WiFi/网段 → 用 TCP 直连，不要加 `--down-rate`**（默认 48000Hz 立体声；那块
  USB 声卡播 48k 是准的：10 秒数据 10.26 秒 ✓）；
- **走 4G（串口）→ 下行用 `--down-rate 12000 --down-channels 1`**，比 8000 明显好，
  总码率 32（上行）+ 24（下行）= 56KB/s，仍在串口 79KB/s 之内；若日志里上行
  `backlog_ms` 开始涨，再退回 8000。
- 想改用别的播放原生速率（比如只认 44.1k 的声卡）：配置里写 `NET_HP_RATE=44100`。

**中继模式下偶发跳音 / 卡一下**

公共 broker 是免费共享的，QoS0 不保证投递（实测每帧投递率在 85%~100% 之间波动），
所以中继模式天生会偶发跳音。按下面的顺序处理：
1. 能不能改用 TCP 直连（见第七节的"内网穿透"）——音质和稳定性都会好一大截；
2. 不能的话，把下行再降一档：`NET_DOWNLINK_RATE=8000`、`NET_DOWNLINK_CHANNELS=1`
   （16KB/s），给上行留出余量；
3. 或者自建 broker（第七节做法 4），这是中继模式里唯一"稳"的方案；
4. 日志里"上行 dropped_frames 增长"= 树莓派发送队列积压丢帧（链路太慢），
   "本地丢 N"= 电脑端发送队列丢帧；两者都能靠降码率缓解。

**"耳机里的声音总比电脑晚半秒"**

抖动缓冲堆太深。`NET_JITTER_MS` 降到 80~120（TCP 下），网络抖动大时再往上调。

**啸叫 / 回声**

电脑在放树莓派送来的声音，同时又把"系统声音"采集回去送给树莓派，就形成回路
（树莓派喇叭 → 树莓派麦克风 → 电脑 → 树莓派喇叭）。**现场演示建议电脑端戴耳机**，
或者第 ③ 块采集来源改成"麦克风"，不要用系统声音回环。

**怀疑模块电源不行**

症状：`lsusb` 一会儿有一会儿没有、`usb0` 反复消失、`dmesg` 里反复枚举 USB。
→ 换独立 5V/2A 电源给模块供电，别用树莓派 USB 口带。

## 十、附录：协议与实现说明

- **帧格式**（TCP 与 MQTT 内的控制帧一致）：4 字节魔数 `BMND` + 类型(音频/JSON) +
  标志 + 序号 + 长度 + 负载。TCP 上音频与控制帧同一条连接（全双工），按类型分流；
  MQTT 上拆成 4 个主题（`{前缀}/{令牌}/up|down|p2c|c2p`），职责单一不必猜类型。
- **两条连接**：上行（树莓派发音频、收控制）与下行（电脑发音频、收统计）各一条，
  某个方向卡住不会拖累另一方向。
- **控制帧**：`hello`（带音频格式）/`welcome`/`stat`（帧数、丢帧、积压、电平）/
  `ping`+`pong`（量往返延迟）/`gain`（远端麦克风增益 0~15）/`hb`（心跳，让对端知道
  自己还在）/`bye`（请求结束本次会话）。
- **树莓派侧代码**：`final_btmic.py` 里的"网络音频"一节，含网络桥脚本正文
  （`NET_BRIDGE_SCRIPT_CONTENT`，运行时写到 `/tmp/btmic_net_bridge.py`，可以直接看）。
- **Windows 侧代码**：`windows/btmic_net_gui.py`，同一个帧协议的最小实现 +
  soundcard 音频收发 + tkinter 界面。
- **不做重传**：音频过期即弃，MQTT 只用 QoS0（重发旧音频只会把延迟越堆越高）。

## 附录 A：串口 + PPP 方案（真机实测调通，2026-09-26）

适用场景：**模块只接 40 脚排针的 TX/RX**（不用它的 USB 口），树莓派通过 PPP 拨号
拿到 `ppp0` 上网。实测环境：Air780EG + AT 固件 V1179 + 联通物联网卡（APN=WONET）
+ 树莓派 5（内核 6.18.50）+ ppp 2.5.2。

### A.1 接线（4 根线）

| 模块主接口 | 接到 | 说明 |
| --- | --- | --- |
| VCC | 外部 5~12V 电源正极（5V/2A 即可） | **USB 口不给板子供电**，必须外部供电 |
| GND | 电源负极 **并与树莓派 GND 共地** | 不共地串口一定不通 |
| TXD | 树莓派 RXD（GPIO15 / 物理第 10 脚） | **交叉接**，3.3V 电平直连不用转换 |
| RXD | 树莓派 TXD（GPIO14 / 物理第 8 脚） | 同上 |

### A.2 打开 GPIO 串口（树莓派 5 必须做）

```bash
# /boot/firmware/config.txt 的 [pi5] 段里加一行（官方 overlay 文档：
#   "uart0-pi5: Enable uart 0 on GPIOs 14-15. Pi 5 only."）
dtoverlay=uart0-pi5
sudo reboot
```

重启后确认（两条都要对）：

```bash
ls -l /dev/ttyAMA0      # 应该出现这个设备
pinctrl get 14,15       # 应显示 14: ... TXD0 / 15: ... RXD0
```

> ⚠️ **不要用 `/dev/serial0` 发 AT**：树莓派 5 上它指向调试串口 `ttyAMA10`，
> 内核 console 挂在上面，命令会被打进系统日志。本程序发 AT 时用的是 `/dev/ttyAMA0`。

### A.3 波特率必须提到 921600（否则带不动音频）

115200 只有约 11.5KB/s，而音频两个方向合计要 48~64KB/s —— 差 5 倍，必须提速：

```bash
sudo python3 final_btmic.py --net-4g-at 'AT+IPR=921600;&W'   # 固定并保存，重启不丢
```

> **不需要记住模块现在是哪个波特率**：`--net-4g-at` 会自动逐个试（115200 / 921600 /
> 460800 / 230400 / 57600 / 9600），谁回 OK 就用谁；`--net-4g-ppp-up` 也会在拨号前
> 把速率统一成 921600。这一条是实测踩出来的：把模块设成 921600 之后，如果某个工具
> 还按 115200 发 AT，模块一声不响，很容易被误判成"模块没通电/坏了"。

实测（`AT+IPR=?` 明确支持固定 921600；**自适应只到 230400，所以必须显式设**）：
走 4G 下载 **78.6 KB/s**（串口 921600 的物理上限约 92KB/s，已经跑到 85%），
ping 223.5.5.5 约 **40ms**。瓶颈在串口，不在蜂窝网络。

### A.4 拨号（一条命令）

```bash
sudo python3 final_btmic.py --net-4g-ppp-up          # APN 默认 WONET（联通物联网卡）
sudo python3 final_btmic.py --net-4g-ppp-up --apn cmnet   # 别的卡用 --apn 指定
# 成功后： ip -brief addr show ppp0  能看到地址； ip route  默认路由切到 4G
sudo python3 final_btmic.py --net-4g-ppp-down        # 挂断
```

拨号要 **30~50 秒**（下面第 1 条那套拆建 PDP 的动作比较慢），`--net-4g-ppp-up` 会等
并最终告出"能上网 ✓"。想在开机时自动拨：往 `/etc/default/bt-mic` 写 `NET_PPP=1`
（必要时加 `NET_PPP_APN=<你的APN>`），网络模式启动时会先拨号。

### A.5 手册上没有、实测才踩到的三个坑（程序内部已全部处理）

1. **直接 `ATD*99#` 会被回 `+CME ERROR: 4`（operation not supported）**：
   模块的内嵌 TCP/IP 协议栈占着 PDP 上下文。必须先 `AT+CIPSHUT`（关掉协议栈）
   再 `AT+CGATT=0` → `AT+CGATT=1`（把 PDP 拆掉重建），然后 `ATD*99#` 才回 `CONNECT`。
2. **模块的 PPP 层会索要 PAP/CHAP，但运营商侧是无鉴权的**（`AT+CGAUTH?` 回
   `1,0,"",""`）。跟着它做 PAP 会被回 `Login incorrect` 而断链；反过来在 peer 里写
   **`refuse-pap refuse-chap`** 就能拨通 —— 这一条决定了成败。
3. **pppd 被强杀或掉线后，模块会留在 PPP 数据模式**，此时发什么 AT 都石沉大海，
   chat 只会一直等到超时（现象是 `chat ... status = 0x3`、ppp0 永远起不来）。
   拨号前先 `+++`（前后各留 1 秒静默）再 `ATH` 把它拉回命令模式即可 —— 程序里
   `net_4g_ppp_escape()` 就是干这个的，chat 脚本里也用 `OK-ERROR` 或匹配兼容
   "本来就在命令模式"（那时 `+++` 会回 ERROR）。

### A.6 带宽预算（照这个配，别贪）

| 方向 | 配置 | 码率 |
| --- | --- | --- |
| 上行（降噪后的麦克风） | 16000Hz 单声道（默认） | 32 KB/s |
| 下行（电脑声音 → 树莓派耳机口） | `--down-rate 8000 --down-channels 1` | 16 KB/s |
| **合计** | | **48 KB/s ✓ 稳**（实测零丢帧） |

两个方向都用 16000Hz 是 64KB/s，已经顶到串口上限，会开始卡顿/丢帧。
**想要更好音质就改用 USB 网卡接法**（正文第二节）：那条路走蜂窝网络本身，
带宽是 Mbps 级，48kHz 立体声都行。

### A.7 实测结果（本方案跑通音频的证据）

```
[网络] 上行: sent_frames=456  dropped_frames=0  backlog_ms=0  level_db=-33.0  peer=windows
[网络] 下行: recv_frames=453  played_frames=455  dropped_frames=0  starved_frames=2  level_db=-8.0
电脑端录到树莓派真实麦克风音频 55.2 秒（每秒 RMS -38~-61 dBFS，峰值 -8.1 dBFS）
```

即：树莓派麦克风 → DeepFilterNet 降噪 → 串口 PPP → 4G → 云端 broker → 电脑，
以及电脑 → 4G → 树莓派耳机口，**两个方向都零丢帧**。
